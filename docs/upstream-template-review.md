# Upstream template review (US-ARCH-10)

## TL;DR

- This repository is a fork of the Obsidian sample plugin. Upstream changed 16 files since the fork point.
- We **took** tooling only: the eslint plugin bump (`eslint-plugin-obsidianmd` 0.1.9 to 0.4.0), upstream's `eslint.config.mts` structure, the esbuild `target` bump, and whitespace fixes in `.editorconfig` and `version-bump.mjs`. The plugin brings its own exact `obsidian` typings, so the API typings `src/` compiles against move from 1.10.3 to 1.12.3.
- We did **not** take any file the rewrite owns: `src/main.ts`, `src/settings.ts`, `manifest.json`, `versions.json`, `tsconfig.json` and the workflows. `scripts/templateGuard.test.ts` now fails, naming the file, if the template's `src/main.ts`, `src/settings.ts`, `manifest.json` or `tsconfig.json` is copied over ours.
- Lint moved from **67 errors / 4 warnings** on master to **53 errors / 83 warnings**. The plugin made many rules warnings and added new ones. Every rule that appeared or disappeared is listed below.

## Glossary

- **Upstream / the template**: `obsidianmd/obsidian-sample-plugin`, the repository this one was forked from. Read only: never pushed to, never merged.
- **Fork point**: `dc2fa22`, the last upstream commit this repository shares. Upstream head at review time: `07ceb81`.
- **Taken**: the upstream change is applied here, whole or in part.
- **Superseded**: this project already replaced the file with its own work, so the upstream change has nothing to land on.
- **Declined**: the upstream change could apply, and we chose not to take it.
- **Parsing error**: eslint could not lint a file at all. Here it is always "not found by the project service": the file is outside `tsconfig.json`'s `include` and not listed in `allowDefaultProject`.

### Rules that disappeared

- `no-restricted-imports` (26 errors). Replaced by `@typescript-eslint/no-restricted-imports`, below.
- `@microsoft/sdl/no-inner-html`, `obsidianmd/no-tfile-tfolder-cast` and `obsidianmd/ui/sentence-case` as **errors**. All three still report, now as warnings.
- Unused eslint-disable directives as **warnings**. They now report as errors.

### Rules that appeared or rose, one sentence each

Every rise below comes from the plugin bump, which also brought the `obsidian` 1.12.3 typings. None comes from this branch's code, and no file under `src/` changed.

- **(parsing error), 1 to 7 in the bump-only run, back to 1.** Plugin 0.4.0 applies its typed config to `.mjs` files, so the four `scripts/*.mjs` files hit the project-service error that `vitest.config.ts` already had, and so did `eslint.config.mts` and the new test. The new config's `allowDefaultProject` lists all six. `vitest.config.ts` stays as on master.
- **(unused eslint-disable directive), error.** The same four directives as before, in four test files under `src/` that disable `import/no-nodejs-modules`. That rule no longer fires on tests, and 0.4.0 reports unused directives as errors.
- **`@typescript-eslint/no-restricted-imports`, 12 warnings.** It replaces the core rule and now allows type-only imports, so it reports only the 12 value imports of `moment` instead of all 26 imports.
- **`eslint-comments/disable-enable-pair`, 4.** A new rule: a file-wide `/* eslint-disable */` must have a matching `eslint-enable`. The four hits are the test files above.
- **`eslint-comments/no-restricted-disable`, 5.** A new rule: 0.4.0 forbids disabling `@typescript-eslint/no-explicit-any` and `@typescript-eslint/no-deprecated`, which four directives in `src/adapters/` and one in `src/settings.ts` do.
- **`eslint-comments/require-description`, 5.** A new rule: a disable directive must say why, and five under `src/` do not.
- **`no-unsanitized/property`, 2.** A new rule that reports the same two `innerHTML` assignments in `src/ui/calendar.ts` as `@microsoft/sdl/no-inner-html`.
- **`@microsoft/sdl/no-inner-html` and `obsidianmd/no-tfile-tfolder-cast`, warning.** Same counts as before, now at warning severity.
- **`obsidianmd/ui/sentence-case`, 12 errors to 14 warnings.** Now a warning, and 0.4.0 checks more UI strings.
- **`obsidianmd/prefer-create-el`, 34.** A new rule: use Obsidian's `createDiv`/`createEl`/`createSpan` helpers instead of `document.createElement`.
- **`obsidianmd/prefer-window-timers`, 12.** A new rule: call `window.setTimeout` and `window.clearTimeout`, so timers work in pop-out windows.
- **`obsidianmd/rule-custom-message`, 8.** A new rule that wraps `no-console`: the eight `console` calls in `scripts/release-check.mjs` and `scripts/verify.mjs`, which are command-line scripts. Master linted both files clean. The bump-only column shows 0 because those files did not parse there.
- **`obsidianmd/no-global-this`, 1.** A new rule: avoid `globalThis`, reported once in `src/ui/test-setup.ts`.
- **`obsidianmd/settings-tab/prefer-setting-definitions`, 1.** A new rule: the settings tab in `src/settings.ts` does not implement `getSettingDefinitions()`, so Obsidian's settings search cannot find its settings.
- **`obsidianmd/settings-tab/prefer-update-over-display`, 5.** A new rule: refresh a settings tab with `this.update()` rather than `this.display()` on Obsidian 1.13+.

Fixing these findings is out of scope here. Files under `src/` belonged to US-ARCH-05 in this wave.
